# POC-004 — Game-ready Spirit Lantern for Godot

## Goal

Move from an image that renders to a structured game asset:

```text
explicit artwork
→ logical cutout parts
→ pivots + hierarchy
→ animation metadata
→ light + collision metadata
→ Godot scene/resources
→ real Godot 4 headless import/run verification
```

## Domain representation

POC-004 introduces five logical parts: body, flame, talisman_left, talisman_right, and tassel.

Each part owns explicit Art IR nodes and has a pivot, parent, z-index, and semantic role.
The idle clip contains deterministic transform tracks for talisman sway, tassel sway, and flame scale.

## Godot export

The exporter must write an isolated Godot project containing individual SVG textures for each logical part, asset.json, a generated spirit_lantern.tscn, a bounded generic cutout runtime script, PointLight2D, Area2D + CollisionShape2D, and a validation scene/script.

No arbitrary user script is accepted by the exporter.

## Current limitation

Each part SVG retains the full source canvas instead of being tightly cropped. This preserves deterministic pivot alignment but is memory-inefficient. It is acceptable for the vertical slice, not for a future production atlas claim.

## Acceptance

POC-004 passes only if:

1. cutout validation passes;
2. all source art nodes are assigned consistently;
3. the MCP exporter produces the five logical parts;
4. Godot 4 imports the generated project headlessly without parser/resource errors;
5. the generated runtime creates AnimationPlayer;
6. the validation scene finds all required parts, light and collision;
7. the game prints GAME_ARTIST_POC004_OK and exits with code 0;
8. exact-head CI is green.

Godot is pinned in CI to an exact stable release and checksum; no latest download is allowed.
