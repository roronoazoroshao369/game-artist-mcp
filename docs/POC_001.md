# POC-001 — Deterministic SVG Art Loop

## Question

Can the repository represent a small game asset as explicit structured geometry, edit it transactionally, render it deterministically, rasterize a preview on Linux, and reject invalid state without using an image-generation model?

## Scope

This POC deliberately does **not** solve autonomous visual critique, cutout rigging, character animation, Godot export, or Blender.

It proves the lower layer those features depend on.

## Pipeline

```text
Art Document (JSON)
        ↓
validate
        ↓
deterministic SVG renderer
        ↓
SVG
        ↓
librsvg
        ↓
PNG preview
```

Mutation path:

```text
expected revision
        ↓
typed batch operations
        ↓
transactional apply
        ↓
validate
        ↓
new revision or reject
```

## First fixture

`examples/jade-spirit-stone/document.json`

The fixture uses only explicit vector geometry:

- polygons;
- Bézier path data;
- ellipse;
- fills;
- strokes;
- transforms.

No text-to-image, image-to-image, diffusion, or external generative model is involved.

## Acceptance gate

POC-001 passes when CI proves:

1. the fixture validates;
2. identical documents render byte-identical SVG;
3. stale revision edits are rejected;
4. invalid edits are rejected atomically;
5. Linux produces a non-empty SVG;
6. Linux produces a non-empty PNG preview;
7. a machine-readable report is emitted.

## What this does not prove

Passing POC-001 does **not** prove that an LLM can create attractive production art.

The next falsification experiment must add an MCP surface and a render → inspect → edit loop so an agent can construct and correct an asset through bounded tool calls.
