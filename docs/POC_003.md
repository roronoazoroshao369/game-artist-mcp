# POC-003 — Visual render → inspect → edit benchmark

## Goal

Test the first genuinely visual part of the product thesis:

```text
LLM intent
→ MCP explicit operations
→ PNG preview
→ visual critique
→ targeted MCP edit
→ PNG preview
```

POC-003 must not be passed merely because a scripted asset renders.

## Iteration 0 — control draft

The repository contains a deterministic MCP client benchmark that constructs an original Ancient Spirit Lantern from explicit vector operations.

CI emits:

- `draft.png`
- `draft.svg`
- `technical-report.json`
- `benchmark.json`

The draft is intentionally treated as **unreviewed**.

Its benchmark must report:

`visualReview: PENDING`

until an actual vision-capable reviewer inspects the PNG.

## Required correction loop

After inspection:

1. record concrete visual defects;
2. modify the existing asset with targeted `document_apply_ops`;
3. render a second preview;
4. preserve before/after evidence;
5. record operation and MCP round-trip counts;
6. run technical validation again.

The correction must be motivated by observed output, not by a pre-scripted fake critique.

## PASS gate

POC-003 passes only when:

- a vision-capable reviewer inspected the actual draft PNG;
- at least one concrete defect was recorded;
- the same asset was edited rather than regenerated from scratch;
- corrected PNG evidence exists;
- hard validator errors are zero;
- total MCP tool round trips remain <= 50;
- correction iterations remain <= 5;
- the reviewer judges the corrected version materially better.

This still does not prove production quality. It only proves that the visual feedback loop can close.
