# POC-003 — Visual render → inspect → edit benchmark

## Result: PASS for feedback-loop mechanics, NOT a production-art claim

POC-003 tested the first genuinely visual part of the product thesis:

```text
LLM intent
→ MCP explicit operations
→ PNG preview
→ real visual critique
→ targeted MCP edit of the same asset
→ PNG preview
```

## Evidence

The first CI-generated Spirit Lantern draft was downloaded and inspected as pixels, not inferred from source geometry.

Observed defects:

- silhouette was readable but too clean and symmetrical;
- talismans read as blank rectangular ears;
- tassel read as a geometric weight rather than cloth;
- frame lacked handmade asymmetry and secondary detail;
- flame was overly centered/stiff.

A second operation batch edited revision 1 of the **same asset** into revision 2. It did not regenerate the document from scratch.

The corrected render was then downloaded and inspected against the draft.

Final review:

- talisman glyphs make the side elements read as intentional talismans;
- the split fringe makes the tassel read more like cloth;
- asymmetry, a rivet, and edge accents add some handmade character;
- silhouette remains readable;
- improvement is real but modest;
- the result is still visually simple and is **not** evidence of production-quality art.

## Measured benchmark

The deterministic run records:

- MCP tool calls: **9**
- explicit art operations: **37**
- preview renders: **2**
- visual correction iterations: **1**
- hard validation errors: **0**
- final revision: **2**

The wall-clock value is recorded per CI run and is not treated as a fixed benchmark constant.

## Gate evaluation

| Gate | Result |
|---|---|
| actual rendered PNG inspected | PASS |
| concrete defects recorded from pixels | PASS |
| same asset edited, not regenerated | PASS |
| corrected PNG preserved | PASS |
| hard technical validation errors = 0 | PASS |
| MCP tool calls <= 50 | PASS (9) |
| correction iterations <= 5 | PASS (1) |
| corrected version materially better | PASS, modest |
| production-quality art proven | **NO — intentionally not claimed** |

## Decision

POC-003 passes the architectural thesis that Game Artist can close a real:

`ACT → RENDER → INSPECT → CRITIQUE → EDIT → RENDER`

loop with bounded MCP calls.

It also exposes the next bottleneck: **artistic abstraction and style richness**, not MCP transport.

POC-004 should therefore focus on a game-ready cutout representation for this same Spirit Lantern while preserving room to improve art quality: logical parts, pivots, hierarchy, animation metadata, Godot export, and runtime verification.
